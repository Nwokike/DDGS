# Dependency Audit — annotated_types 0.8.0

Owner goal: every dependency covered. Role: constraint vocabulary (`Annotated[int, Gt(0)]`) consumed by pydantic v2 (2.13.5 in this env) — annotated_types itself performs **zero validation**; it only declares metadata dataclasses that a parser (pydantic, cattrs, msgspec…) interprets. DDGS (`ddgs/` package) does **not** import annotated_types directly today (grep: no hits); it arrives transitively via `pydantic/types.py` (`PositiveInt = Annotated[int, Gt(0)]`, `Strict*`, `con*`, `StringConstraints` → `Interval`/`MultipleOf`/`Len`).

## 1. COMPLETE API INVENTORY (entire package is one module: `__init__.py`, 417 lines)

**Comparison bounds:** `Gt(gt)` — value must be `> gt`; `Ge(ge)` — `>= ge`; `Lt(lt)` — `< lt`; `Le(le)` — `<= le` (all frozen slot dataclasses over `BaseMetadata`, work on any type supporting the operator: numbers, dates, strings, sets).
**Grouped bounds:** `Interval(gt, ge, lt, le — all kw-only, default None)` — bundles inclusive/exclusive bounds in one object, `__iter__` unpacks into zero or more `Gt/Ge/Lt/Le` (empty `Interval()` yields nothing); `GroupedMetadata` — runtime-checkable `Protocol` base for such bundles, subclass **must** implement `__iter__` (else `TypeError` at class creation), recognized unpacked both as `Annotated[int, Field(...)]` and PEP-646 `Annotated[int, *Field(...)]`; `BaseMetadata` — empty base class, exists only so parsers can `isinstance(x, BaseMetadata)` while traversing annotations.
**Multiplicity:** `MultipleOf(multiple_of)` — `value % multiple_of == 0` (Python) **or** `int(value/multiple_of) == value/multiple_of` (JSON Schema) — library documents both, consumer picks; pydantic implements one, check before relying on floats.
**Lengths:** `MinLen(min_length)` — `len(value) >= min_length`; `MaxLen(max_length)` — `len(value) <= max_length`; `Len(min_length=0, max_length=None)` — `GroupedMetadata` unpacking into `MinLen`/`MaxLen` (min 0 yields no `MinLen`, `max None` yields no `MaxLen`); all three coerce `min/max_length: Annotated[int, Ge(0)]`.
**Timezone:** `Timezone(tz)` — `tz=None` requires naive datetime, `tz=...` (Ellipsis) requires aware-any-tz, `tz=<str|tzinfo>` requires that specific zone (upstream notes pinning a zone is usually poor design).
**Unit:** `Unit(unit: str)` — physical-quantity tag (e.g. `Unit('m/s')`, dimensionality as `Unit('[time]')`); **no enforcement whatsoever**, interpretation left to consumer (pint/astropy conventions suggested).
**Predicates:** `Predicate(func)` — arbitrary `func(value)` truthiness check with smart `__repr__` (named funcs, bound methods, method descriptors); `Not(func)` — negation wrapper (`__call__` returns `not func(v)`); predefined string aliases (all `Annotated[_StrType, Predicate(...)]`, **not classes — cannot instantiate**): `LowerCase` (`str.islower`), `UpperCase` (`str.isupper`), `IsDigit` + plural alias `IsDigits` (`str.isdigit`), `IsAscii` (`str.isascii`); predefined numeric aliases (all `Annotated[_NumericType, Predicate(...)]`): `IsFinite` / `IsNotFinite` (`math.isfinite`), `IsNan` / `IsNotNan` (`math.isnan`), `IsInfinite` / `IsNotInfinite` (`math.isinf`).
**Docs (PEP 727):** `Doc(documentation: str)` — frozen slot dataclass carrying a docstring into `Annotated` metadata; `DocInfo = Doc` (backwards-compat alias); `doc = Doc` (**the class itself, not an instance** — usage is `Annotated[int, doc("…")]` calling the class); if `typing_extensions` is installed its `Doc` is used instead (try/except import at lines 399–416).
**Protocols:** `SupportsGt/Ge/Lt/Le/Mod/Div` — comparison/dunder `Protocol`s typing the bound fields (no runtime effect).
**Version:** `__version__ = '0.8.0'`.
**Negative inventory (asked-about names that do NOT exist in 0.8.0):** no `Eq`/`Ne` classes; no `get_metadata()` helper; no `_internal/`, `docs/`, or `pydantic_compat` submodules — single-file package (`__init__.py` + `test_cases.py` + `py.typed` marker only).
**Star-import trap:** `Unit`, `IsDigit` (singular), `IsAscii`, and `Not` are importable attributes but **absent from `__all__`** — `from annotated_types import *` silently drops them (only plural `IsDigits` is exported).
**pydantic compat notes (verified against pydantic 2.13.5 `types.py`):** pydantic imports `annotated_types` + `BaseMetadata/MaxLen/MinLen` directly; builds `PositiveInt/NegativeInt/NonNegativeInt/NonPositiveInt` (+Float) from `Gt/Lt/Ge/Le`, `conint/confloat/condecimal` (+`Strict*`) from `Interval`+`MultipleOf`, `constr/conbytes/conlist/conset/confrozenset` from `Len`; `Timezone` maps to `AwareDatetime/NaiveDatetime`-family handling; `GroupedMetadata.__iter__` unpacking is honored (custom bundles work in pydantic fields); `doc`/`Doc` flows into JSON Schema `description`; `Predicate` is enforced at validation but degrades in JSON Schema (opaque — no schema constraint emitted); `Unit` is ignored by pydantic entirely.

## 2. LATENT CAPABILITIES FOR DDGS (ranked honestly — ALL conditional on DDGS adopting pydantic models, which is planned but not present)

1. **`Interval` + `Len` on future Settings/History models = single source of truth for kani tools.** `Annotated[int, Interval(ge=1, le=50)]` / `Annotated[str, Len(1, 200)]` on a pydantic model simultaneously validates at runtime AND emits `minimum/maximum/minLength/maxLength` in `TypeAdapter(M).json_schema()` — the same model feeds kani `AIFunction(json_schema=…)` instead of today's hand-written dicts. Kills schema/validator drift. Highest value, near-zero marginal cost once models exist.
2. **`doc("…")` descriptions surfacing in tool parameter text.** pydantic copies `Doc` into JSON Schema `description`, which kani/openai pass to the model as parameter help — one-line docstrings on future arg-model fields improve tool-use accuracy for free. Second-highest value for the same reason (no extra code path).
3. **`Timezone` for history/receipt timestamps.** `Annotated[datetime, Timezone(timezone.utc)]` on future `HistoryEntry`/receipt models forces tz-aware UTC at load instead of today's naive-datetime ambiguity in raw JSON dicts. Real but narrow — only matters when datetimes enter models.
4. **`Gt/Ge/Lt/Le` single bounds via pydantic `Field` are equivalent, prefer `Field`.** `Field(ge=0)` already compiles to the same core schema as `Annotated[int, Ge(0)]` — DDGS model code should use `Field` kwargs (idiomatic, discoverable) and reserve raw annotated_types imports for `Interval`/`Len` bundles and cross-library portability. No new capability, just style guidance.
5. **`Predicate`/`LowerCase`/`IsDigits` — low value, prefer explicit validators.** Opaque to JSON Schema (no constraint emitted, so the model never sees it) and exception behavior on type mismatch is explicitly unspecified upstream (may skip, raise, or propagate). A `@field_validator` with a clear error message beats `Predicate` everywhere DDGS would use it.
6. **`MultipleOf` / `Unit` — effectively no DDGS use.** Step constraints on counts and physical-unit tags have no plausible settings/history/tool-arg application; `Unit` is unenforced metadata pydantic ignores.

## 3. GOTCHAS

- **No runtime behavior without a parser:** `Annotated[int, Gt(4)]` on a plain dataclass/function does nothing — bounds only bite inside pydantic models / `TypeAdapter` / `validate_call`. Raw-dataclass use needs manual `__post_init__` checks (same class of bug as today's `SearchResult.__post_init__` null-guarding, just relocated).
- **`Predicate` exception semantics unspecified:** `Annotated[int, Predicate(str.isdigit)]` (func raising on wrong type) may silently skip, statically error, or propagate depending on the library — never use `Predicate` where input type is uncertain; guard with a real type annotation + validator.
- **`MultipleOf` dual semantics:** Python-modulo vs JSON-Schema-division differ on floats/negatives — verify which pydantic implements before constraining any float step.
- **Empty bundles vanish:** `Interval()` / `Len(0, None)` yield zero constraints (valid everything) — a programmatically built bundle with all-`None` args silently constrains nothing.
- **`GroupedMetadata` subclass contract:** forgetting `__iter__` raises `TypeError` at class definition, not at use — loud, but confusing if met halfway through a refactor.
- **`doc` is inert documentation:** no validation effect; tools that don't extract `Annotated` metadata (anything pre-PEP-727) ignore it silently.
- **Case aliases are `Annotated`, not types:** `LowerCase[str]`-style subscription is the only valid use; `isinstance(x, LowerCase)` and `LowerCase(...)` are both errors. Same for all `Is*` aliases.
- **Star-import drops `Unit`/`IsDigit`/`IsAscii`/`Not`** (missing from `__all__`, see inventory) — always import by name.
- **Bound cross-type comparisons:** `Gt(datetime(...))` on a `date` field (or vice versa, cf. `test_cases.py:30`) relies on mixed comparison support — keep annotation type and bound type in the same family.
