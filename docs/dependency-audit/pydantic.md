# Dependency Audit — pydantic v2.13.5 (pydantic-core 2.46.5)

Owner goal: 100% capability utilization. Consumer path: DDGS → kani (`validate_call` on tool functions, hand-written JSON schemas) → openai; DDGS itself persists settings/history/state as raw JSON + dicts (`src/core/state.py`, `src/core/storage_paths.py`, `src/services/storage_service.py`, `src/services/conversation_service.py`, `src/services/cache_service.py`).

## 1. COMPLETE API INVENTORY (grouped by module)

**`main.py` — BaseModel core:** `BaseModel` — declarative model with `__init__(**data)` validating on construction; `model_fields` (cls property → `dict[str, FieldInfo]`); `model_computed_fields` (cls property); `model_extra` (extra keys when `extra='allow'`); `model_fields_set` (which fields were explicitly set); `model_construct` (no-validation constructor for trusted data); `model_copy(update=…, deep=…)` (copy + patch); `model_dump(mode='python'|'json', exclude/include, by_alias, exclude_none/unset/default, round_trip, warnings)`; `model_dump_json(...)` (same, returns JSON str/bytes); `model_json_schema(...)` (per-model JSON Schema); `model_parametrized_name` (generic specialization name); `model_post_init(context)` (post-validation hook); `model_rebuild(force, types_namespace…)` (resolve forward refs); `model_validate(obj, strict, from_attributes, context)` (validate arbitrary object); `model_validate_json(json_data, strict, context)`; `model_validate_strings(obj, strict…)` (all-strings input, e.g. env/CLI); `create_model(name, __base__, __config__, field defs…)` (runtime model factory); `__pydantic_init_subclass__` / `__pydantic_on_complete__` (subclass lifecycle hooks); deprecated shims still present — `dict()`→`model_dump`, `json()`→`model_dump_json`, `parse_obj()`→`model_validate`, `parse_raw()`→`model_validate_json`, `parse_file()`, `from_orm()`→`model_validate(from_attributes)`, `construct()`→`model_construct`, `copy()`→`model_copy`, `schema()/schema_json()`→`model_json_schema`, `validate()`→`model_validate`, `update_forward_refs()`→`model_rebuild`.
**`fields.py` — fields:** `Field(default, alias, title, description, examples, gt/ge/lt/le, min/max_length, pattern, strict, coerce_numbers, discriminator, frozen, exclude, repr…)` (field metadata + constraints); `FieldInfo` (introspectable field descriptor, `asdict()`); `PrivateAttr(default)` / `ModelPrivateAttr` (non-field private state, `_x`); `computed_field(alias, repr, exclude, return_type…)` + `ComputedFieldInfo` (derived read-only property included in dumps/schema).
**`aliases.py` + `alias_generators.py`:** `AliasPath('a', 0, 'b')` (validate from nested path); `AliasChoices('a', 'b')` (first-match alias); `AliasGenerator(validation_alias, serialization_alias)` + `to_pascal/to_camel/to_snake` (bulk alias conventions, e.g. camelCase wire ↔ snake_case code).
**`functional_validators.py`:** `field_validator(*fields, mode='before'|'after'|'wrap'|'plain', check_fields…)` (per-field validators, classmethod); `model_validator(mode='before'|'after'|'wrap')` (whole-model validators); `BeforeValidator/AfterValidator/PlainValidator/WrapValidator` (reusable `Annotated` validators); `SkipValidation` (escape hatch annotation); `ValidateAs` (validate-then-cast marker); `InstanceOf` (isinstance-check annotation).
**`functional_serializers.py`:** `field_serializer(*fields, when_used='always'|'unless-none'|'json'…)` (custom per-field output); `model_serializer(mode='plain'|'wrap')` (whole-model dump override); `PlainSerializer/WrapSerializer` (`Annotated` serializer funcs); `SerializeAsAny` (serialize subclass, not base declared type).
**`config.py` — model_config options worth knowing:** `ConfigDict` with `strict`, `extra='ignore'|'allow'|'forbid'`, `frozen`, `populate_by_name`/`validate_by_alias`+`validate_by_name`, `use_enum_values`, `validate_assignment`, `validate_default`, `arbitrary_types_allowed`, `from_attributes` (ORM objects), `loc_by_alias`, `alias_generator`, `ignored_types`, `allow_inf_nan`, `json_schema_extra`, `json_encoders` (legacy), `revalidate_instances`, `ser_json_timedelta/temporal/bytes/inf_nan`, `val_temporal_unit`, `val_json_bytes`, `str_to_lower/upper/strip_whitespace/min/max_length`, `title` + `model_title_generator`/`field_title_generator`, `coerce_numbers_to_str`, `regex_engine`, `validation_error_cause`, `defer_build`, `cache_strings`, `hide_input_in_errors`, `use_attribute_docstrings`, `protected_namespaces`; `with_config(config)` (attach ConfigDict to non-model types e.g. TypedDict/dataclass).
**`validate_call_decorator.py`:** `validate_call(func=None, *, config=None, validate_return=False)` (validates function args/return at call time; plain or parametrized decorator; works on sync+async).
**`type_adapter.py`:** `TypeAdapter(type, config…)` — validate/serialize *any* annotation (not just models): `validate_python/validate_json/validate_strings`, `dump_python/dump_json`, `json_schema/json_schemas`, `get_default_value`, `rebuild`.
**`root_model.py`:** `RootModel[root_type]` (model wrapping a single root value, e.g. a list/dict payload with validation).
**`dataclasses.py`:** `dataclass(...)` (pydantic-validated stdlib-style dataclass), `rebuild_dataclass`, `is_pydantic_dataclass`.
**`json_schema.py`:** `GenerateJsonSchema` (customizable schema backend — subclass to change all schema output), `model_json_schema(cls…)` / `models_json_schema([(model, 'validation'|'serialization')…])` (standalone schema gen incl. multi-model `$defs` bundle), `WithJsonSchema({...})` (hand-override schema for a type), `Examples` (schema examples metadata).
**`annotated_handlers.py`:** `GetCoreSchemaHandler / GetJsonSchemaHandler` (hook points for custom `__get_pydantic_core_schema__` / `__get_pydantic_json_schema__` integrations).
**`types.py` — constrained/special types:** `Strict/StrictStr/StrictInt/StrictFloat/StrictBool/StrictBytes`, `conint/confloat/constr/conbytes/conlist/conset/confrozenset/condecimal/condate` + `StringConstraints`, `PositiveInt/NegativeInt/NonNegativeInt/NonPositiveInt` (+Float variants), `FiniteFloat`, `AllowInfNan`, `UUID1…UUID8`, `FilePath/DirectoryPath/NewPath/SocketPath`, `Json` (parse JSON-encoded string field), `Secret` (generic secret base) / `SecretStr` (masked repr, `get_secret_value()`) / `SecretBytes`, `PaymentCardNumber` (+`PaymentCardBrand`, Luhn-validated), `ByteSize` (human-size int, `.human_readable()`), `Base64Bytes/Base64Str/Base64UrlBytes/Base64UrlStr` + `EncodedBytes/EncodedStr` + `EncoderProtocol`, `ImportString` (dotted-path → imported object), `PastDate/FutureDate/PastDatetime/FutureDatetime/AwareDatetime/NaiveDatetime`, `GetPydanticSchema` (custom-type hook), `Tag/Discriminator` (see unions), `JsonValue` (any JSON value), `FailFast` (stop on first error), `OnErrorOmit` (drop failing items from collections).
**Discriminated unions:** `Discriminator(field_or_callable)` + `Tag('value')` on union members — `Field(discriminator='type')` routes `Annotated[Cat|Dog, Field(discriminator='type')]` by tag for fast exact validation (internals in `_internal/_discriminated_union.py`).
**`networks.py`:** `AnyUrl/AnyHttpUrl/HttpUrl/FileUrl/FtpUrl/WebsocketUrl/AnyWebsocketUrl` (+`UrlConstraints`: max_length, allowed_schemes, host_required), `EmailStr/NameEmail/validate_email` (needs `email-validator` package), `IPvAnyAddress/IPvAnyInterface/IPvAnyNetwork`, DSNs: `PostgresDsn/CockroachDsn/AmqpDsn/RedisDsn/MongoDsn/KafkaDsn/NatsDsn/MySQLDsn/MariaDBDsn/ClickHouseDsn/SnowflakeDsn` (multi-host DSN parsing with user/password/host/port/db).
**Serialization modes (de/serialization):** validation `mode='validation'` vs serialization `mode='serialization'` infos (`ValidationInfo`/`SerializationInfo`/`FieldSerializationInfo` carry `context`, `field_name`, `mode`); dump flags `mode='json'` (JSON-safe), `by_alias`, `exclude_unset` (only set fields — receipts/diffs), `exclude_defaults`, `exclude_none`, `round_trip` (dump re-validatable); strict vs lax per-call (`strict=True` on any validate/dump call).
**`model_extra`:** populated dict of undeclared keys when `extra='allow'` — forward-compatible persistence (unknown future keys survive round-trip).
**Function adapters:** `validate_call` (above); `experimental/arguments_schema.generate_arguments_schema(func…)` (build CoreSchema of a signature — what kani-adjacent tooling uses).
**Dataclasses support:** full — `@pydantic.dataclasses.dataclass` validates `__init__`/assignment (with `validate_assignment` config), supports stdlib field semantics + rebuild.
**Errors handling:** v2 has **no `ErrorWrapper`** (`error_wrappers.py` is an empty husk) — errors surface as `pydantic_core.ValidationError` (re-exported at top level) with `.errors(include_url…)` → list of `{loc, msg, type, input, ctx}` dicts, `.error_count()`, `.json()`; config `hide_input_in_errors`, `validation_error_cause`, `loc_by_alias` tune output; `errors.py` holds programmer errors (`PydanticUserError`, `PydanticUndefinedAnnotation`, `PydanticImportError`, `PydanticSchemaGenerationError`, `PydanticInvalidForJsonSchema`, `PydanticForbiddenQualifier`, `PydanticErrorCodes`); `warnings.py` versioned deprecation ladder (`PydanticDeprecatedSince20…212`) + `PydanticExperimentalWarning`, `CoreSchemaGenerationWarning` family.
**`pydantic_core` exported API (from pydantic's perspective only — Rust binary, `.pyi`+`.pyd`):** re-exports `ValidationError`, `ValidationInfo`, `SerializationInfo`, `FieldSerializationInfo`, `ValidatorFunctionWrapHandler`, `SerializerFunctionWrapHandler`, `OnErrorOmit`; plus `core_schema.py` (schema-builder DSL powering every custom type) and `SchemaValidator/SchemaSerializer` reachable via `TypeAdapter`/`__get_pydantic_core_schema__`.
**Getters (v1→v2 note):** v1 `GetterDict`/`from_orm` are gone — replaced by `model_validate(obj, from_attributes=True)` reading plain attributes (customize via `__get_pydantic_core_schema__` if exotic access needed).
**`TypeVarTypeAdapter`?:** does **not** exist in 2.13.5 — generics are handled by subscripting (`Model[int]`) and `TypeAdapter(List[T])`-style binding; no separate adapter class to learn.
**Everything else:** `version.VERSION/version_info()/version_short()/check_pydantic_core_version()`; `color.Color/RGBA` + `parse_*` helpers (CSS color validation); `tools.py`/`parse.py`/`schema.py`/`json.py`/`validators.py`/`class_validators.py`/`decorator.py`/`datetime_parse.py`/`env_settings.py` (legacy shims, mostly deprecated); `deprecated/*` (8 v1-compat modules) and `v1/*` (26-file full v1 copy — quarantined, do not import); `experimental/pipeline.py` (`_Pipeline` validate/transform/constrain combinator DSL — experimental), `experimental/missing_sentinel.MISSING` (unset-vs-None sentinel); `plugin/*` (`PydanticPluginProtocol`, `ValidatePython/Json/StringsHandlerProtocol`, `get_plugins`, `PluggableSchemaValidator` — third-party validation observability hooks); `mypy.py` (mypy plugin); `utils.py`/`typing.py` (internal-ish helpers); `_internal/*` (29 private modules — metaclass, schema gen, decorators — not public API).

## 2. LATENT CAPABILITIES FOR DDGS (ranked by value × effort)

1. **Generate tool JSON schemas FROM pydantic models (single source of truth).** kani's `AIFunction` accepts an explicit `json_schema` today fed by hand-written dicts; `TypeAdapter(ArgsModel).json_schema()` / `model_json_schema()` produces it from the same model that validates — one definition drives both the model prompt and the runtime check. Kills schema/validator drift, the highest-risk bug class in tool calling.
2. **Replace hand-rolled dict settings/history with typed models + validators.** `src/core/state.py` (`SearchResult.__post_init__` null-guarding), `storage_service.py`, `conversation_service.py`, `cache_service.py` all `json.load/dump` raw dicts — a `Settings`/`HistoryEntry`/`Receipt` BaseModel with `field_validator`s catches corrupt state files at load (`model_validate_json`) instead of mid-render `AttributeError`s, and `exclude_unset`/`exclude_none` keeps files minimal.
3. **`TypeAdapter` for validating JSON coming from scrape tools.** Search/YouTube/Innertube payloads (`innertube_client.py`, engine results) are untrusted JSON — `TypeAdapter(List[SearchResultModel]).validate_python(raw)` with `OnErrorOmit` drops malformed rows instead of the current all-or-nothing try/except that degrades whole rows to "Parse Error" placeholders.
4. **`validate_call` on DDGS's own tool functions (beyond kani's blanket wrap).** kani applies bare `validate_call(inner)` (no config, no `validate_return`); DDGS service-layer functions with `**kwargs`-heavy signatures get zero checking — targeted `@validate_call(config=ConfigDict(strict=True), validate_return=True)` on storage/network boundaries turns silent coercion bugs into loud `ValidationError`s.
5. **`model_dump` for receipts persistence.** `license_token.py`, `reasoning.py`, `conversation_service.py` hand-assemble dicts for disk — `model_dump(mode='json', exclude_none=True)` gives JSON-safe, schema-conformant receipts for free, re-validatable with `model_validate` (round-trip guarantee via `round_trip=True`).
6. **Discriminated unions for conversation event types.** Chat/conversation streams (`chat_agent.py`, `conversation_service.py`) branch on string `type` tags with if/elif chains — `Annotated[TextMsg|ToolCall|Receipt, Field(discriminator='type')]` validates-and-routes in one step with exact errors per variant.
7. **`SecretStr` for GATEWAY-like secrets.** API keys/tokens in settings/license flows (`license_service.py`, `tls.py`, engine keys) currently plain `str` — `SecretStr` masks them in every log/repr/dump by default (`get_secret_value()` only at use site), eliminating accidental secret leakage into receipts/logs.

## 3. GOTCHAS

- **v1→v2 renames (never copy old snippets):** `parse_obj→model_validate`, `parse_raw→model_validate_json`, `parse_obj_as→TypeAdapter`, `.dict()→model_dump`, `.json()→model_dump_json`, `.schema()→model_json_schema`, `.construct()→model_construct`, `.copy()→model_copy`, `.validate()→model_validate`, `@validator→@field_validator`, `@root_validator→@model_validator`, `class Config→ConfigDict (model_config)`, `GetterDict/from_orm→model_validate(from_attributes=True)`; v2 raises `ValidationError` (pydantic_core), never v1 `ErrorWrapper`.
- **Import cost:** `import pydantic` pulls the compiled `pydantic_core` extension; top-level names are lazily mapped via `_dynamic_imports`/`getattr_migration`, so `from pydantic import BaseModel` stays cheap but first model definition pays schema-build cost — define models at module import, not per-call; `model_rebuild()` only for forward refs.
- **`validate_call` + `**kwargs` (kani uses it):** kani wraps as bare `validate_call(inner)` — no config, no return validation; unannotated params and `**kwargs: Any` pass through **unchecked**, and defaults are NOT re-validated unless `validate_default=True`; extra kwargs raise `ValidationError` only if the signature lacks `**kwargs`; the wrapper also mangles `inspect.iscoroutinefunction` (kani works around it via `_inner_is_coro`) — replicate that workaround if wrapping async tools manually.
- **`EmailStr` needs the optional `email-validator` package** (import error at validation time, not install time); ` networks` DSN types parse but do not connect — still need runtime connection checks.
- **`pydantic_core` binary compatibility (Android builds):** `pydantic_core` is Rust — this env ships `_pydantic_core.cp312-win_amd64.pyd` pinned to **exactly 2.46.5** (`_COMPATIBLE_PYDANTIC_CORE_VERSION`, enforced by `_ensure_pydantic_core_version()`); any Android/termux target needs its own `cp3XX-<arch>` wheel at that exact version — pin `pydantic==2.13.5` + `pydantic-core==2.46.5` together and never float one without the other.
